# JFS/JFR 阶段6：组合并发、错误和退出验证

## 代码及测试

移除已不用的CAS容量预留、全池Acquire入口和仅测试使用的释放接口，避免与当前“先准备、按快照接收、owner限制设备配额”的语义混淆。CQ轮询/重新arm发生错误时，停止JFS并推动owner取消队列、通知等待者。

新增4个确定性用例：部分前缀成功但后缀EINVAL，只取消对应连接，其他连接继续发送；暂满但没有任何在途CQE可推进时报告错误而非卡死；致命错误停止队列并取消多连接排队项；关闭等待仍在post内的owner及并发生产者，静默后才清理队列/context。

原先只验证旧CAS预留接口的用例删除，软件并发超量与设备严格限额由阶段3的提前CQE/小配额用例覆盖。合计71项Bazel mock测试通过；6个owner/并发发布/部分提交/等待登记竞态/关闭repost相关测试额外重复100轮，600次通过。

未启用ASAN/TSAN；没有据此声称已经排除所有数据竞争。验证依据是确定性时序、重复竞态用例和真机压力。
