# JFS 阶段 3：MPSC、链式提交与 TX slot 去锁

## 实现

- 发送方先构造稳定的 WR/SGE/context/数据引用，单节点最多 32 WR，再发布至对应 JFS 的 exchange+link MPSC。发布后由 JFS 持有数据，Cut 返回已接收字节数；硬件暂时只接受前缀时，其余部分留在队列，不再次消费 IOBuf。
- incoming_head 与 RUNNING/KICK 独立。生产者和 TX CQE 共用 KickDrain；已有 owner 时记录 KICK，owner 退出前以 CAS 检查新通知，避免 CQE 到达与退出交错造成遗留任务。
- owner 持续排空，单次链式 post 最多 32 WR，不等待凑批。软件接收计数允许并发窗口内短暂超量，设备计数严格按 SQ 深度限制。
- TX post/poll 不再持有 slot mutex，不维护 TX pending set。submitted 固定数组只用于 DMA 静默后的关闭枚举，CQE 仍直接按 user_ctx 路由。提交引用保护 CQE 早于 post 返回的 context。
- 操作门将关闭位与活动计数合并，关闭先阻止进入、摘除事件、等待操作退出，再删除硬件队列和释放存储。RX 锁及 context 集合留待阶段 5。
- 暂满保留未接受后缀；其他错误终止关联 Socket；已接受部分由 CQE 或成功删除硬件队列后的静默边界回收。若提供者返回暂满且没有任何在途 WR 能推动重试，则报告错误，避免永久卡队列。

## 验证

使用 Bazel，真实 SDK 及 mock 分别构建。原 59 项用例继续覆盖，新增 4 项，合计 63 项：

1. 就绪链长度 1、31、32、33、65，实际 post 为 1、31、32、32+1、32+32+1。
2. 软件接收 4 个 WR、设备只容纳 2 个，post 内提前处理 CQE；不依赖新生产者仍能排空 2+2。
3. 首个 owner 阻塞在 post，另外 31 个独立逻辑链路并发发布并返回，实际 post owner 始终只有一个，提交链为 1+31。
4. owner 摘到已发布但尚未链接的节点，等待链接完成后正常提交。

已有部分 post 用例改为验证：成功前缀不会重发、未接受后缀由 JFS 保留、调用者数据只消费一次、seq 不重复分配、最终字节流完整且计数归零。跨 JFS 重排用例通过两批提交显式制造跨队列，不依赖单批轮询分散。

真机命令及原始日志保存于项目外层 `测试/阶段3_真机验证_20261104/`。145 服务端、151 客户端，NUMA3 CPU288–303、udmac1d1e2、event/multi，2 JFS、2 JFR、SQ64/RX512、QD32；1K/8K/100K 各单链路和32链路，50 iterations。短测试时延统计为0，不用于性能比较。

启用 `--vmodule=urma_resource_pool=1` 可记录每次链长度及 post 结果；正式性能测试关闭该日志。

固定首选 hash、随机4备选和首选等待尚未在本阶段启用，属于阶段4。
